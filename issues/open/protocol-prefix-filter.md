# 订阅协议里没有前缀字段：客户端要换过滤范围只能升版本，而升版本会让所有客户端硬失败

> 提出者：由 #4 按 `AGENTS.md` §2.2 步骤 4 的 `split` 决策拆出。原作者仍是 esidx，
> 本文的现象与实测均来自 #4，未新增任何未经测量的断言。

## 现象

`struct sfa_subscribe_req` 只有 8 字节（`sfa.h:64-67`）：

```c
struct sfa_subscribe_req {
    uint32_t mask;        /* SFA_EV_* 位掩码；0 表示取消订阅 */
    uint32_t reserved;
};
```

其中 `reserved` 是一个 32 位的空位，但装不下前缀。唯一能带上过滤范围的地方是消息本身，
所以过滤范围只能由**代理**决定（#4 保留的 `--prefix`），不能由**客户端**决定。

代价在版本校验上（`libsfa.c:31-35`）：

```c
if (n != (ssize_t)sizeof(w) || w.version != SFA_PROTO_VERSION) {
    close(fd);
    errno = EPROTO;
    return -1;
}
```

严格相等、无协商、无兼容路径 —— 改消息形状就等于**全量客户端重连**。

## 影响

**这是 sfa 目前所有扩展的定价机制。** 它解释了三条看似无关的决策：

| 决定 | 为什么不升版本 |
|---|---|
| #2 加 `SFA_EV_UNRESOLVED` 位 | 消息结构未变，位掩码可扩展 → 不升 |
| #1 用 `SFA_EV_OVERFLOW` 补发 desync | 复用已有信号形状 → 不升 |
| #4 的协议过滤塞进定长结构 | 结构必变 → 要升 → 全量重连 |

**同一件事的定价差异高达两个数量级**：加一个 bit 免费，改一个字段要全量重连。
这个落差本身就是「协议形状没留扩展位」造成的后果，代价见 #7。

**量级取决于未测量的比例。** #4 的决策记录已经写明了前置条件：先在真实机器上量出
前缀过滤能滤掉多少比例的事件（客户端每批次打印的 `outside the root` 计数）。
那个数字**现在还拿不到** —— 之前量到的 49% 来自 esidx 构造的 fixture，不是繁忙机器的形状。

## 建议

**先量，再决定。现在不要写实现。**

```sh
grep -o '([0-9]* events so far, [0-9]* outside the root' serve.log | tail -1
```

- 量出来 **5%** → 协议这条路就此关掉，本篇按「收益不足」关闭，`--prefix`（#4）做足即可；
- 量出来 **80%** → 才值得讨论改协议形状，届时先解决 #7 的扩展性问题，
  否则下一个要改结构的人还会撞同一堵墙。

真要做，形状上应该走**变长的第三种消息类型**（一个长度前缀 + 前缀字节），
而不是把 `char prefix[SFA_MAX_PATH]` 塞进定长结构 —— 后者让每次订阅请求涨到 4104 字节，
而实际前缀用不到几百字节。

**前置依赖**：#7（协议没有版本协商、消息头没有 reserved 字段）。在 #7 有结论之前动协议形状，
会把「让所有客户端重连」这件事再叠一次。
